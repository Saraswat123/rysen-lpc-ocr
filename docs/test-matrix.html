Fix timeline
Bug #1
Celery worker: No module named 'extractor'
Forked Celery subprocesses don't inherit '' from cwd in sys.path. Runs 02–04 all failed at task import.
Fix: added sys.path.insert(0, _ROOT) to worker/tasks.py + celery_app.py, launched with PYTHONPATH=$(pwd).
Fix → Run 05
First successful end-to-end extraction
50 rows inserted, job marked done in 128s. Blank template PDF so scores null — pipeline confirmed working.
Run 06 · Real data
14 rows with actual C1–C4 scores (Beawar, LPC 3-5)
First filled student card. All 14 domain rows have non-null scores. Confirms vision model can read handwritten values. 38s — fastest successful run.
Runs 07–08 · Circuit breaker
CB accumulated failures from load test → OPEN
Load test (50 jobs × minimal.pdf) ran against real OpenRouter — failures triggered CB. Subsequent real jobs blocked for 30s per CB cycle.
Fix: restart worker (CB resets to CLOSED on fresh start).
Bug #2
Rust serde parse fail: domains Vec vs HashMap
Model returns domains as a JSON object keyed by domain name: {"Early Literacy": {c1,c2,...}}.
Rust struct expected Vec<DomainData> with a name field — schema mismatch. Runs 09–10 got HTTP 200 but serde_json::from_str failed.
Fix: changed to HashMap<String, DomainScores>, updated extraction_to_rows to iterate (name, scores) tuples.
Bug #3
reqwest .text() failed on large responses
.text().await returned Err on 18–19 KB vision responses (encoding/stream issue).
Fix: switched to .bytes().await + String::from_utf8_lossy(). Added tracing::debug!(body_len) for visibility.
Bug #4
300s reqwest timeout too short for free model
Run 13 hit exactly 300s → timeout killed response stream. Free-tier model latency varies 128–300s+.
Fix: raised .timeout(600s), split .connect_timeout(30s) separate.
Fix → Run 14 · Pipeline stable
All fixes applied — HashMap struct + bytes() + 600s timeout
Run 14: status=200 OK body_len=19000 → 50 rows inserted → done in 168s. No warnings. CB stays CLOSED. Commit d8dfec7 pushed to GitHub.
